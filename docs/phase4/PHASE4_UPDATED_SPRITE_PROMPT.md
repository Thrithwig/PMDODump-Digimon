## Low-usage operating model

1. Inspect reusable project state once per batch; persist a compact manifest and checkpoint.
2. Make species decisions once: source identity, anatomy/rig mapping, size class, palette, clip/action mappings, key poses, flight/ground policy, and reference source.
3. Let deterministic local scripts enumerate, render, convert, assemble, validate, and create previews without an agent call per frame or animation.
4. Reuse verified caches and resume pending/failed work. Do not rerender unchanged accepted frames or repeatedly read large logs.
5. Return compact summaries with counts, timings, cache misses, failures and artifact paths. Keep verbose logs on disk. Agents inspect the summary and specific defects, not every successful log line.
6. Review each new animation set using compact all-direction sheets/playback; do not describe unchecked material as visually approved. Automated checks prioritize anomalies but cannot approve anatomy or aesthetics.
7. Preserve review decisions against exact artifact hashes. Unchanged approved outputs need not be re-reviewed; changed outputs become pending review.
8. Reserve user escalation for genuine choices or blocked authority. Implementer self-review is not independent approval.

Use a practical shared library plus JSON configuration, not a distributed service or elaborate framework. New species should usually need configuration, not a fork of Agumon's code.

## Source and animation selection

Reuse legitimate locally extracted Time Stranger models and existing dsts-extractor/tooling. Do not reinstall or re-extract already available assets. Keep proprietary raw assets local and ignored. Record source/tool hashes and reference revisions.

For each species, inspect mesh/materials, skeleton, native clips/durations, orientation, animated bounds and root motion. Do not transplant Agumon's bone names, UV masks, pupils or offsets into unrelated anatomy.

Native 3D anatomy and motion are primary. A suitable PMDO reference supplies missing motion/timing/readability guidance; Charmander Sprite 0004 is Agumon's reference, not a universal template. Choose references by body shape, locomotion and attack mechanism. Pin reference revisions. Document procedural motion, repeated cycles, retiming and copied reference timing honestly.

Target action categories for complete production sets:
Walk; Physical Attack (engine Attack); Special Attack (engine Shoot); Sleep; Hurt; Idle; Swing; Double; Hop; Charge; Rotate.
User category numbers are NOT PMDO engine action IDs. Resolve actual registry names/indices and copy chains.

For loops, sample evenly across a cycle without duplicating its endpoint. For one-shot actions, audition anticipation/contact/recoil/recovery and align event frames deliberately. Avoid blind endpoint sampling (Agumon's first Hurt attempt looked idle). Do not assume the largest movement or evenly spaced time is the correct impact pose. Character Special Attack does not imply projectile/effect asset generation.

## Rendering and pixel contract

- Transparent rendering at every capture layer; exported alpha strictly 0/255, transparent background, no white rectangle or fringe. Wait for explicit model/textures/animation/geometry readiness. Avoid incompatible Chrome command-mode background flags with CDP.
- PMDO row order: Down, DownRight, Right, UpRight, Up, UpLeft, Left, DownLeft. Existing canonical azimuths: 0,315,270,225,180,135,90,45 degrees. Verify source orientation and use explicit per-model corrections.
- Orthographic camera, stable lighting, fixed species scale/root anchor, and adequate margins over the union of selected clips/directions. Never auto-fit each frame or direction. Keep offset/shadow transforms identical to sprite transforms.
- Use approved census assignments and More distinction neutral-pose visible heights: Small 16–24 px, Medium 26–32 px, Large 34–44 px, Huge 46–56 px. Include silhouette appendages; exclude transparent canvas padding and airborne ground gap. Use one species scale across directions/actions with margins for animated extensions. Preserve approved prior sprites. The 56 px Huge ceiling needs actual narrow-corridor visual/traversal checks with one tall and one broad representative before broad use. See task outputs/sprite-production/height-policy.json for interpolation and Baby targets.
- One-pixel exact-black outer silhouette; restrained anatomical internal seams. Protect head/jaw from generic crease damage. Preserve real nose, mouth, armor and markings using species-specific inspected settings.
- Preserve visible eye anatomy, depth occlusion and travel-facing pupils where appropriate. Hidden eyes need no forced pixel. Compound eyes do not get invented humanoid pupils.
- At the initial native-size Idle inspection, explicitly compare visible eyes against the local skin/face tone. If the skin is light and eyes are source-visible, give each visible eye a restrained one-pixel black edge, even when its iris already has some contrast; carry it consistently through actions where that eye remains visible. Derive the eye region from source anatomy/material mapping; confine the border to the eye edge, never the whole head or an occluded face, and do not invent a pupil or an extra eye. At 17-19px a complete dark loop may overpower the face, so audition an anatomy-bounded contour at native size, inspect representative all-direction and complete front/side frames, and record any partial-edge design explicitly for review. Pabumon and Poyomon require this correction to their existing lab candidates.
- Audit the effective source eye/face material, not just the extracted GLB's PBR fallback or a texture-atlas thumbnail. Check mesh UV set, shader texture slots, alpha/mask channels, matcap/shine layers and the native compositor before approving Idle. If a white fallback layer obscures mapped dark facial anatomy, correct the source-backed layering in an opt-in renderer path and re-render a fresh candidate; never paint an assumed pupil or treat a green mask channel as visible eye color. Compare a facial close-up and native-size all-direction sheet, then run protected-asset parity.
- Plan a stable species palette across requested clips, reserving important eye/mouth/teeth/marking colors before quantization. Target <=64 opaque colors per sheet; record species-wide union separately. Accepted Agumon has 65 in the union because its unchanged Idle palette and two mouth colors coexist; preserve and document that exception. Never erase mouth anatomy merely to force a global limit.
- Ground contact must use the appropriate feet/root evidence, not universally the lowest opaque pixel (which can be a hand, tail or wing). Preserve intentional jump lift and flyer bob above a ground-anchored shadow. Agumon's reviewed per-frame grounding is a compatibility rule, not a default for all bodies.
- For a non-Idle, non-Physical-Attack action, a transient one- or two-pixel cut at the fixed shadow line is acceptable when a pose dips below it. Alpha-trim only the offending below-shadow pixels in the specific action/direction/frame; do not rescale or reposition the whole pose, alter the shadow, or change neighboring frames. Never apply this clipping allowance to Idle or Physical Attack. Audit colored body overlap separately from a stray black contour pixel, and compare the corrected pose at native size before acceptance.
- Prefer projected animated head/center/hand bones with reviewed mappings. Update camera matrices before projection. Anatomical left/right is not screen left/right. Report template-assisted mappings and limitations; marker presence alone is not anatomical correctness.

## Production lessons from the first two Babies

- Gate each distinct anatomy at Idle, then build its other ten actions. Use source-model neutral height and a single fixed pixels-per-unit scale for Idle and action sheets. A larger action canvas is margin, not permission to enlarge the creature. Botamon's ground anchor and Kuramon's hovering anchor are separate policies.
- Treat source geometry as the source of facial truth. Botamon's ear-base marker substitutes and Kuramon's body-side marker substitutes are documented interpretations, not literal hands. Kuramon has one central eye: preserve its source white disk and dark ring, occlude it in side/back views, and close it for Sleep without inventing a paired eye or pupil.
- Inspect root motion before packing. If a native clip's horizontal root travel would push a stationary action to the canvas edge, lock local X/Z consistently while preserving native Y, rotation, scale and deformation. Verify the resulting input records and full-frame margins. Do not infer clipping from a cropped preview; inspect the actual full action cell.
- Review an all-action/all-direction sheet and a complete front/side frame sequence, not just a few selected poses. Record accepted subtleties. Botamon's Shoot is a body-release gesture and Kuramon's Shoot likewise lacks verified projectile ejection. Kuramon's Double has two visual contacts but only one engine HitFrame. Do not silently equate visual pulses with gameplay hits.
- Native PMDO import/save/load is a distinct gate from structural validation and live play. The accepted Baby packages remain lab candidates until separately authorized integration and real terrain/playback inspection. Before accepting revisions, compare approved Idle bytes, frozen Agumon decoded pixels plus geometry, and hashes of protected assets.
- Preserve attested render caches and candidate immutability. A config/timing decision that does not change exact render inputs should use cached frames; a changed pose/framing/renderer input must miss cache. Measure browser startups and actual render misses, but do not infer model-token savings from render-time benchmarks.
- For grounded soft bodies with separately animated particles or beads, distinguish ground-contact anatomy from floating ornament. Audit all action cells against the fixed shadow row. A one-pixel black contour from an appendage is not equivalent to colored body penetrating ground. Pabumon's Rotate needed two uniformly revised native sample times to remove three colored-body overlaps; retain the first candidate as rejected evidence and revalidate only the fresh revision. Document when Hop shares an Attack native arc and when its lift is subtle.
- For translucent or pale gradient bodies, per-sheet color count is not enough: audit the union across actions and transitions. Poyomon's first set had 62 colors per action but 560 distinct colors overall. Reassembling from exact cached frames with a shared, approved-Idle-anchored 64-color palette and reserved source mouth tones fixed the drift without changing silhouettes or Idle. Treat source texture marks and eye meshes separately; a dark mark in an overlay atlas is not automatically a visible pupil. Confirm flight/ground from native root and skinned underside, not the apparent silhouette alone.
- Punimon's first Idle sheet was rejected despite passing structural/native checks: white e01h GLB fallback eye meshes hid the source dark eye openings mapped via b01. Source material routing exposed the alpha/matcap and mask roles; use that preflight for similar species. Preserve the rejected candidate as evidence and approve only a separately rendered, validated revision before generating actions.
- Punimon's completed full-action candidate uses the corrected Idle and native expression layers. Its first full pass had two Hurt cells (UpRight/Up frame2) extending two pixels below the shadow. The user approved clearing only the 4+5 offending opaque pixels in those cells; the revised 34-file package changes only Hurt-Anim.png, not Idle, Attack, offsets, shadows or timing. Treat this as a narrow action-specific exception, not a new global renderer rule.
